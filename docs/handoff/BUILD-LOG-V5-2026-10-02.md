## Backend (`docs/BACKEND.md`)
`POST /api/contact` (one Route Handler, no new dependency): same-origin (CSRF) check, JSON-only, 8 KB cap, honeypot, per-client and global rate limits, the same validation as the form (strings only, length limits, control characters stripped), then one document in Cloud Firestore through its REST API with a service-account JWT signed by `node:crypto`. No IP or user agent is stored; `expiresAt` = 12 months for a Firestore TTL policy; `firestore.rules` deny all client access. If storage is not configured or fails the API answers 503 and the form falls back to the visitor's own email app (so it works today without any setup). **`node scripts/test-api.mjs` runs 26 end-to-end cases against a mock Google** (JWT verified with the public key): all pass. **Not verified against real Firestore**: that needs the club's Firebase project and three env vars (`FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`; steps in BACKEND.md, about 10 minutes). I did **not** create a Firebase project: the only one on the logged-in CLI is an unrelated game, and creating the club's needs your Google account and billing choices. The privacy policy (legal text, untouched) must be checked against the backend before it is switched on.

## Security pass
- **Headers** (`next.config.ts`): CSP tightened (no remote script origins, `img-src` limited to self/data/blob/i.ytimg.com, `object-src 'none'`, `connect-src 'self'`, `upgrade-insecure-requests`), plus COOP, `X-Permitted-Cross-Domain-Policies`, `poweredByHeader` off, 30-day cache on `/images` and `/models`. Scripts keep `'unsafe-inline'` (Next's inline bootstrap); no `eval`. QA confirms zero console/CSP errors on every route.
- **Checked and fine**: `dangerouslySetInnerHTML` only in JSON-LD (escapes `<`); legal Markdown renders as React elements with a scheme allow-list; every `target=_blank` has `rel="noopener noreferrer"`; legal slugs are checked against a fixed map; no secrets in the repo; `.env*` ignored (only `.env.example` tracked); `npm audit` 0 vulnerabilities; `robots.txt` disallows `/api/`.
- **Found by an independent code review (high effort) and fixed**: section headings were invisible in server HTML without JS (now hidden only when scripting is on); a spoofable `X-Forwarded-For` could bypass the rate limit (now the platform's own address header, else the last hop); the mobile menu let the page scroll behind it under Lenis (`data-lenis-prevent`); the vortex still faded out before its textures loaded (a Ready gate inside Suspense); a lost WebGL context left an empty hero (both scenes now fall back to the poster/stack); the hero scroll listener read layout on every scroll even off screen (now rAF-batched and only while visible); a hover-only team link was invisible on tablets; server-rendered CTAs could show "register" for up to an hour after close (page revalidates every 5 minutes, labels derive from the timeline); an unmeasured shader warm-up hack used backdrop-filter against the design rules (removed).

## Lag
Measured with real mouse-wheel scrolling over the whole page in headed Chrome (`scripts/lag-v5.mjs`): at normal CPU 800+ frames, **2 frames over 34 ms (0.2%), 0 long tasks**; at 4x CPU throttle (a deliberately weak machine, and phones skip the WebGL scenes) about 11% over 34 ms. Changes: the WebGL scenes are never disposed mid-scroll (that was a 200-400 ms task); the vortex scene is built in the background after load (idle), its shaders are compiled in parallel, textures are 768 px, have no mipmaps and upload one per idle period; the hero light sweep and scroll read are cheap. **Residual**: the very first time a machine draws the tilted map and the vortex, Chrome compiles GPU shaders (a one-off 100-250 ms stall seen only on a cold driver cache; traced to `FinishPaintRenderPass` plus ANGLE worker tasks). It disappears on the second visit or run and I could not remove it without removing the effect.
