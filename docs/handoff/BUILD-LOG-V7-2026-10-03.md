## Phase notes
- **A/B (audits).** `scripts/overlap-audit.mjs` (text line boxes and images per section; excused: `aria-hidden` decoration and `[data-overlap-ok]`) and `scripts/gap-audit.mjs` (gap between sections, blank share; the full-viewport hero, the ticker band and the pinned vortex dive are `data-gap-ok`). Before: 5 route/width combinations overlapped, 87 sections failed (Numbers, Reach and Flagship carried about 3,000px of pinned dead scroll; gaps of 190 to 300px). After: **0 and 0** on 11 routes x 5 widths (360/768/1024/1440/1920). The spec's `--section-y: clamp(56px, 7vw, 104px)` contradicts its own 160px gap limit (2 x 104 = 208), so the token is `clamp(40px, 5vw, 68px)`: a deliberate deviation. The audits were tuned while building (sr-only, aria-hidden, hairline and box rules); each rule is commented in the script.
- **C.** Cursor removed (R1).
- **E (vine).** Three candidates drawn and screenshotted at 1440 (`docs/handoff/v7/vine-candidates-A-B-C.jpg`, generator `vine-geometry.mjs`). **A (curved vine, mirrored leaf pairs) chosen**: B's leaves read as arrowheads, C is lopsided. 34 SVG nodes, 10 leaves, orange bud only at the tip. It grows through a CSS scroll timeline (no script while scrolling). The IntersectionObserver fallback is for browsers without scroll timelines (Firefox at the time of writing); the Firefox e2e run passed with it, but I did not look at it visually. Idle sway of 2 degrees and a one-time unfurl, both off under reduced motion. Hidden below 1100px (no mobile version).
- **F (vortex GPU).** Measured by `scripts/vortex-perf.mjs` (10 s steady scroll through the dive; frame times from `requestAnimationFrame`, long tasks, WebGL draw calls, GPU-process CPU share from CDP `SystemInfo.getProcessInfo`, an approximation of GPU load, not the GPU's own counter). Renderer here: NVIDIA RTX 4060 Laptop. At DPR 1.5: draw calls per frame **12.3 to 6.2**, drawing buffer **2160x1350 to 1800x1125**, GPU-process share **24.1% to 20.7%**; at DPR 1 **22.7% to 19.6%**; at 4x CPU throttle **20.1% to 17.5%**. p95 frame time was already 17ms (60fps) before and after, with zero long tasks, because this GPU is not the bottleneck. At rest in the section: 182 draw calls in 10s (the first frame only) instead of continuous rendering. What changed: demand-driven frames (a frame only when scroll or damping needs one, 22ms minimum, 33ms once frames run over 20ms for 30 in a row), DPR cap 1.25 (hero too), panels outside the visible depth window hidden (5 or 6 drawn), plain-opacity paper grain (it used `mix-blend-mode: overlay` over the whole viewport), and the capability gate now also refuses 4 GB or less memory and Intel or software GPU renderers. Textures were already 768px WebP without mipmaps; there is no post-processing; context-loss handling is untouched. **Uncertain on the owner's machine:** if Chrome runs on the integrated GPU the gate now serves the stacked version; on a discrete GPU the numbers above apply. The owner can check Windows Graphics settings and `chrome://gpu`. Not measured: a real integrated-GPU laptop, 6x throttle, Safari.
- **G.** Nav: mark + "E-Club NITW"; the counter shows only "NN / NN" (the long label was the bug). `ClubMark` shows the logo file when `site.logos.eclub` is set, else the site's own bar glyph. The favicon is that same glyph (`icon.svg`).
- **H, I.** Partner model and ownership map (`docs/CONTENT-MAP.md`). Removed from Initiatives: the repeated poster wall. Removed from Sponsors: the invented "three ways in" tiers.
- **J.** `scripts/build-events.mjs`. No EXIF existed (WhatsApp exports). All 18 frames kept (the owner's selection); near-duplicates noted, not rejected: The Pitch League 3 and 6 (same presenter and room), 4 and 6. Pitch’er Perfect 3 has glare on the screen. Old photos, `media.ts`, `archive.ts`, `build-media.mjs` deleted.
- **K.** Four tabs, API `type` enum with an explicit allowlist, 47 API checks (was 36). The campus address line is not shown: nitw.ac.in could not be read (script-rendered).
- **Photo rule bent deliberately:** V5's "raw photos only in Gallery" is relaxed to Gallery, event pages and the Home/Initiatives cover rows (owner decision), and `qa-v5` now asserts exactly that. `qa-v5` was also rewritten for the time-based map, the vine and the contact tabs.
