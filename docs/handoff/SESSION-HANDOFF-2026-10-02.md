## 11. Lessons, mistakes, patterns to keep
- Research before designing; verify before claiming done; never invent a fact (the most consistent owner expectation). Missing content becomes an honest TODO/CONFIRM, never a plausible guess.
- Earlier tools' build logs overstated progress once ("all pages finished" when only a stub existed): trust only measured evidence and re-run audits.
- A "bare framework" budget check beat chasing an impossible 180 KB. Measure before promising.
- Do not judge performance on `next dev`; use `next start`; reject slow-machine Lighthouse runs (`scripts/lh.mjs` prints a benchmark).
- Do not loosen CSP (it forbids wasm-unsafe-eval and blob workers, so glTF models use quantization instead of Draco/Meshopt). Claude Code must not touch CI/CSP/env/.github in overnight runs.
- Claude Code push was denied once (V3); worked for V4. Never push to main; no PRs from overnight runs.
- AI image tools: no text, logos or faces; check at full size; rerun if weak.
- India map depiction is legally sensitive: use a compliant outline, log its source, have faculty review.
- Do not attribute anything to the club that the club did not supply; do not mix Business Club NITW.
- "Gallery only if the reference sites have one": IIT Bombay has a Gallery nav item, so a Gallery stays, restricted to raw event photos.
